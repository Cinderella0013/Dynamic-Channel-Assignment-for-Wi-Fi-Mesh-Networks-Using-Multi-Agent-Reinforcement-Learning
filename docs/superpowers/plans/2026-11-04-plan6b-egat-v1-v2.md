# Plan 6b: EGAT v1 (anchored MAPPO) and EGAT v2 (GAT-Q + RAES) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the two EGAT variants from spec addendum §3 and §4. Add validation-based checkpoint selection for **every** learner. Train v1 and v2 once each (seed 0, 100k steps) on the Plan 6a simulator, then score them with the pre-registered composite against the Plan 6a reference table to pass or fail the gate in spec §6.

**Architecture:**

- **v1 — `EGATv1Agent(EGATAgent)`** in `mesh/model/agent.py`. Same network as Plan 4. Adds four things:
  - a frozen copy of the policy after BC, `π_BC`, with a KL anchor to it;
  - fixed λ;
  - an n-step (semi-MDP) advantage for the channel head;
  - a lower learning rate after BC.
- **v2 — `EGATv2Agent`** in a new file, `mesh/model/v2.py`. It reuses the Plan 4 `EGATNet` encoder, and its two heads read as Q values. Training is Double DQN on the actions actually executed, with a DQfD-style BC warm start. Each step it acts by running the pipeline Q → RAES → migration refinement → Action(`queue_preserve=True`).
- **Checkpoint selection** lives in `mesh/rl/train.py` (`val_every`). It applies to Q-neutral, Yuan, Li, EGAT and both variants alike, so no method gets an advantage from it.

**Tech Stack:** Python ≥ 3.11, NumPy, PyTorch 2.11 + CUDA 12.8, pytest.

**Spec:** `docs/superpowers/specs/2026-11-03-egat-v1-v2-design.md` (§3, §4, §6 gate).

## Global Constraints

- **Training distribution:** S1–S6 only, as in Plans 3–4. B and C stay held out for testing.
- **Budget:** 100k env steps per learner, BC steps included. Validation episodes are evaluation only: they never learn and do not count toward the budget.
- **Validation:** scenarios S1–S6 with seeds 1000, 1001, 1002, evaluated greedily every `val_every = 10_000` steps. Test seeds are 0–4, so the two sets never overlap. The kept checkpoint has the best mean validation reward. For BC learners, the end of BC counts as one validation point.
- **v1 defaults:**

  | Setting | Value |
  |---|---|
  | `lam_start = lam_end` | 0.1 |
  | `kl_start` → `kl_end` (anneal) | 0.1 → 0.01 |
  | `semi_mdp` | True |
  | `lr_after_bc` | 1e-4 |
  | Everything else | Plan 4 `EGATConfig` defaults |
- **v2 defaults:**

  | Setting | Value |
  |---|---|
  | Replay buffer | 50k env steps |
  | Batch | 32 env steps |
  | Soft target update τ | 0.01 |
  | γ | 0.98 |
  | ε (anneal over 50k steps) | 0.3 → 0.02 |
  | Learning rate | 3e-4 |
  | `bc_steps` | 10k |
  | DQfD margin | 0.8 |
  | RAES weights `a`, `b`, `g` | 1.0, 1.0, 1.0 |
  | Migration `margin` | 0.1 |
  | `k_max` | ceil(0.1·n) |
  | `cooldown` | 3 |
  | `raes_order` | "backlog" |
  | Flags `raes`, `migration_control`, `queue_preserve` | all True |
- **v2 joint Q:** `Q(u, a) = Q_ch(u, c) + Q_rt(u, j)` for `a = c*K + j`. This is an additive decomposition. The TD target uses Double DQN on each head: the online network picks the action under its mask and the target network scores it.
- **Registration:** `LEARNERS` gains `"egat_v1": EGATv1Agent` and `"egat_v2": EGATv2Agent`. The eval CLI's `--policy` choices gain the same names.

## Review Focus

1. **Migration refinement rejects every proposed move** (for example all nodes in cooldown). The current assignment is kept, the decoded action equals `obs`'s channels and parents, and nothing crashes. Test: Task 4 `test_refinement_can_reject_everything`.
2. **Every node in RAES finds all channels reserved by neighbours.** It still picks the least-bad channel, and costs stay finite. Test: Task 4 `test_raes_saturated_neighbourhood`.
3. **The KL anchor right after BC, before any PPO update.** The KL to `π_BC` is 0 and the loss is unchanged. Test: Task 1 `test_kl_zero_at_bc_end`.
4. **The best checkpoint is restored at the end of training** even when the last validation was worse. Test: Task 3 `test_keeps_best_validation_checkpoint`.
5. **v2 learns from the executed action, not its argmax.** Replay stores `last_action_idx` after refinement. Test: Task 5 `test_replay_stores_executed_action`.

### Task 1: v1 — KL anchor to the BC policy

**Files:** Modify `mesh/model/egat.py` and `mesh/model/agent.py`. Test `tests/test_egat_v1.py`.

**Interfaces:**
- New `EGATConfig` fields, with defaults chosen so that plain `EGATAgent` (Plan 4) behaves exactly as before: `use_kl_anchor=False, kl_start=0.1, kl_end=0.01, semi_mdp=False, lr_after_bc=None`.
- **`EGATAgent.bc_fit`:**
  - When `use_kl_anchor` is set, it keeps `self.bc_net`, a deep copy of `self.net` with `requires_grad_(False)`, in eval mode.
  - When `lr_after_bc` is set, it changes the optimiser's learning rate.
- **`EGATAgent.update`:**
  - When `use_kl_anchor` is set, it adds `κ_t · KL(π_θ ‖ π_BC)`, summed over the route head and the channel head (channel only on decision steps).

### Task 2: v1 — semi-MDP channel credit

**Files:** Modify `mesh/model/agent.py`. Test: add to `tests/test_egat_v1.py`.

**Interfaces:**
- `EGATAgent.nstep_adv(rewards (T,n), values (T,n), dones (T,), last_value (n,), n_steps) -> (T,n)`:
  - `A_t = Σ_{k<m} γ^k r_{t+k} + γ^m V_{t+m} − V_t`, with `m = min(n_steps, steps to episode end, steps to rollout end)`.
  - It bootstraps from `last_value` at the end of the rollout and from 0 at `done`.
- In `update`, when `semi_mdp` is set, the channel log-prob term uses the n-step advantage with `n_steps = t_c`, normalised over alive agents. The route term keeps GAE. The PPO ratio stays one joint ratio, and the surrogate becomes `ratio_route·A_route + is_chan·ratio_chan·A_chan`, each clipped separately.

### Task 3: Validation-based checkpoint selection (all learners)

**Interfaces:**
- `train(method, steps, seed=0, n=20, out=None, log_every=5000, val_every=None, **agent_kwargs)`:
  - When `val_every` is set, it runs every `val_every` steps and once more at the end of training.

### Task 4: v2 — RAES and migration refinement (pure functions)

**Files:** Create `mesh/model/v2.py` (planner half). Test `tests/test_v2_raes.py`.

**Interfaces** (NumPy only, no torch):
- `raes(obs, slots, q_ch: (n,6), q_rt: (n,K), route_mask: (n,K) bool, a=1.0, b=1.0, g=1.0, order="backlog", downtime=1) -> tuple[np.ndarray c (n,), np.ndarray j (n,), np.ndarray ch_score (n,6)]`:
  - **Order:**
    - `"backlog"`: decreasing `backlog`, ties broken by hop count, then id.
    - `"parents"`: tree depth of the current `next_hop`, parents first.
  - **Per node u, in that order:**
    - **Interference** `I[c]` = Σ over reserved conflict neighbours v with `c_v = c` of `(1 + backlog_v)`.
    - **Co-channel load** `L[c]` = Σ over conflict neighbours v whose **current** radio-1 channel is `c+1` of `offered_load_v`.
    - **Migration cost** `M[c]` = `1[c+1 ≠ current radio1] · downtime · backlog_u`.
    - **Score:** each of `q_ch[u]`, `−I`, `−L` and `−M` is z-scored over the 6 channels (a constant row becomes 0). `score = z(q) − a·z(I) − b·z(L) − g·z(M)`.
    - `c_u = argmax score`, and `ch_score[u] = score`.
  - **Route:** `j_u = argmax over valid slots of (q_rt[u] − g·M_rt)`, where `M_rt = 1[slot parent ≠ current parent]·downtime·backlog_u`, z-scored the same way.
  - Returns 0-based channel indices `c` and slot indices `j`.
- `refine(obs, slots, c, j, ch_score, q_rt, cooldown_left: (n,) int, margin=0.1, k_frac=0.1) -> tuple[c (n,), j (n,), moved (n,) bool]`:
  - **Current assignment:** `c_cur = radio1 − 1`; `j_cur` = the slot index of the current parent, or `j` itself when the current parent is not in the slots.
  - **Gain:** for each node proposing a channel or parent change, `gain = (ch_score[u,c] − ch_score[u,c_cur]) + (q_rt[u,j] − q_rt[u,j_cur])` (q_rt z-scored per row).
  - **A move is a candidate only if** `gain > margin` and `cooldown_left[u] == 0`.
  - **Accepting moves:** take candidates by decreasing gain, skip any whose conflict neighbour has already been accepted this round, and stop at `k_max = ceil(k_frac · n_alive)`.
  - **Rejected nodes** keep `c_cur` and `j_cur`.
  - Returns the final `c`, the final `j`, and `moved`.

### Task 5: v2 agent — GAT-Q, Double DQN, DQfD warm start, queue preservation

**Files:** Modify `mesh/model/v2.py` (agent half). Test `tests/test_v2_agent.py`.

**Interfaces:**
- `class EGATv2Agent: __init__(self, seed=0, device=None, **overrides)`.
  - **Network:** `self.net = EGATNet(cfg)` with `cfg = EGATConfig(use_ko_prior=False, **encoder-relevant overrides)`, and `self.target` as a copy of it. The chan and route logits are read as `Q_ch` and `Q_rt`.
  - **Flags:** `raes`, `migration_control`, `queue_preserve`, `raes_order`, `a`, `b`, `g`, `margin`, `k_frac`, `cooldown` (defaults from Global Constraints).
  - **State:** `self.cooldown_left (n,)`, which resets at `obs.t == 0`.
- **`act(obs, explore=False) -> Action`:**
  1. Reset GRU and cooldown at `t == 0`.
  2. Forward the network to get `Q_ch`, `Q_rt`.
  3. If `explore`, then for each node with probability ε, replace its `Q_ch` and `Q_rt` rows with standard-normal noise.
  4. If `raes`, call `raes(...)`. Otherwise use the masked per-node argmax.
  5. If `migration_control`, call `refine(...)` and set `cooldown_left[moved] = cooldown`. Otherwise every proposal is executed.
  6. Decrement cooldowns.
  7. `a = c*K + j`, decode it, and set `action.queue_preserve = cfg.queue_preserve`.
  8. Set `last_action_idx = a`, and store the network inputs and `h_prev` in `_pending`.
  - **During BC with `explore=True`:** act as Ko through the interface (`ko_action_idx`), still with `queue_preserve`.
- **`learn(obs, a_idx, rewards, next_obs, done) -> dict`:**
  - Push `(pending inputs, h_prev, a_idx, rewards, next inputs, h_next, done, alive)` into the replay buffer.
  - **During BC:** collect only. At `bc_steps`, run `bc_fit()`, which does `bc_epochs` passes over the BC buffer of the DQfD loss `max_a[Q(a) + 0.8·1[a ≠ a_Ko]] − Q(a_Ko)` per head, plus the TD loss. It then copies the network to the target and moves the BC transitions into replay.
  - **Online:** one Double DQN update per `learn` call once replay holds at least `batch` items.
    - Target: `y = r + γ(1−done)·[Q_ch^tgt(s', argmax_c Q_ch^on(s')) + Q_rt^tgt(s', argmax_{j∈mask} Q_rt^on(s'))]`.
    - Loss: Huber of `Q_ch(s,c) + Q_rt(s,j) − y` over alive agents, then a soft target update.
- `save(path)` and `load(path, device=None)` follow the EGAT pattern. `reward_lam(step, total)` returns 0.1 (spec §3.2 applied to v2 as well; disclosed). `set_budget(steps)` handles the ε schedule.
