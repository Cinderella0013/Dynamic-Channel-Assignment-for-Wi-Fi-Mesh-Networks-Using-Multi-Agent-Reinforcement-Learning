# คู่มือการใช้งาน EGAT-MAPPO

คู่มือนี้อธิบายตั้งแต่การติดตั้งจนถึงการสร้างผลลัพธ์ของวิทยานิพนธ์ "การกำหนดช่องสัญญาณและเส้นทางร่วมกันในเครือข่าย Wi-Fi mesh แบบหลายฮอปด้วย EGAT-MAPPO" ใช้ได้บน Windows, Linux และ macOS ส่วน ns-3 รันบน Linux หรือ WSL (Windows Subsystem for Linux) เท่านั้น

ทุกคำสั่งในคู่มือตรวจกับโค้ดที่ commit นี้แล้ว (`mesh/rl/train.py`, `mesh/eval/suite.py`, `mesh/eval/composite.py`, `mesh/ns3/suite.py`, `runs/v10/*.sh`) ถ้าต้องการดูขั้นตอนทั้งหมดแบบย่อและเร็ว ให้ดู [คู่มือเดโม](../../demo/คู่มือเดโม.md)

## 7. การฝึกโมเดล

คำสั่งหลัก (`python -m mesh.rl.train`):

| argument | ความหมาย | ค่าในวิทยานิพนธ์ |
|---|---|---|
| `--method` | `egat`, `li`, `yuan`, `q_neutral` (และ `egat_v1`, `egat_v2` ที่เป็นรุ่นทดลอง) | |
| `--steps` | จำนวน env step | 100000 |
| `--seed` | training seed | 0-4 |
| `--val-every` | ตรวจ validation ทุกกี่ step (เลือก checkpoint ที่ composite บน validation ดีสุด) | 10000 |
| `--set k=v` | แก้ค่า scenario (ตัวจำลอง) | `$S` |
| `--agent-set k=v` | แก้ config ของ learner | `use_gru=false` สำหรับโมเดลหลัก |
| `--out` | ไฟล์ checkpoint | `runs/v10/ckpt/<ชื่อ>_s<k>.pt` |

โมเดลหลัก (EGAT ไม่มี GRU) ตาม `runs/v10/nogru.sh`:

```bash
mkdir -p runs/v10/ckpt
for k in 0 1 2 3 4; do
  python -m mesh.rl.train --method egat --steps 100000 --seed $k --val-every 10000 $S \
    --agent-set use_gru=false --out runs/v10/ckpt/egat_nogru_s$k.pt > runs/v10/ckpt/egat_nogru_s$k.log 2>&1
done
```

baseline ที่เรียนรู้ได้ (ตาม `runs/v10/job.sh <method> <k>`):

```bash
for m in li yuan q_neutral egat; do for k in 0 1 2 3 4; do
  python -m mesh.rl.train --method $m --steps 100000 --seed $k --val-every 10000 $S --out runs/v10/ckpt/${m}_s$k.pt
done; done
```

ablation (ตาม `runs/v10/job_abl.sh <label> <flag> <k>`): `--agent-set use_edge_feat=false` (`egat_noedge`), `use_gru=false` (`egat_nogru`), `use_ko_prior=false` (`egat_noko`), `use_bc=false` (`egat_nobc`) ชื่อ flag ตรวจได้ใน `mesh/model/egat.py` (`EGATConfig`)

สิ่งที่เกิดขึ้นระหว่างฝึก EGAT: 10,000 step แรกเป็น behaviour cloning (BC) จาก Ko แล้วต่อด้วย MAPPO; ทุก `--val-every` step และตอนจบ BC จะคำนวณ composite เทียบ Ko บน topology validation (seed 1000-1003, A+B) โดยใช้น้ำหนักแบบ EMA และเก็บตัวที่ดีที่สุด log จะมีบรรทัด `egat val step ... composite ...` ไฟล์ `*_val<step>.pt` คือ candidate ระหว่างทาง ไฟล์ `<ชื่อ>_s<k>.pt` คือตัวที่เลือกแล้ว

## 8. การเลือก hysteresis margin

margin เลือกบน validation (A+B x topology 1000-1003) ด้วยกฎ worst-case: เลือก margin ที่ composite ต่ำสุดเมื่อเทียบ Ko, M0, Li, Yuan, Q-neutral สูงที่สุด ตาม `runs/v10/nogru.sh`:

```bash
mkdir -p runs/v10/wc
python runs/v10/wc_val.py ko; python runs/v10/wc_val.py m0
for k in 0 1 2 3 4; do for b in li yuan q_neutral; do python runs/v10/wc_val.py $b $k; done; done
for k in 0 1 2 3 4; do for m in 0 0.5 1 2 3 4; do python runs/v10/wc_val.py nogru $k $m; done; done
python runs/v10/fair_pick.py nogru > runs/v10/fair_nogru.txt     # บรรทัดสุดท้าย: chosen margin 2
```

Li+H และ Yuan+H (การทดสอบความเป็นธรรม) ใช้กฎเดียวกัน grid `0 0.25 0.5 1 2 4 8 16`: `python runs/v10/wc_val.py li <k> <m>` แล้ว `python runs/v10/fair_pick.py li` (ผล: margin 1 ทั้ง Li และ Yuan) แต่ละคำสั่งรันอิสระกัน จึงรันขนานด้วย `xargs -P` ได้ ดู `runs/v10/fair_fresh.sh`

## 9. การประเมินผล

คำสั่งหลัก (`python -m mesh.eval.suite`):

| argument | ความหมาย |
|---|---|
| `--suite A,B,C` | กลุ่ม scenario: A = S1-S6, B = B1-B5, C = C1-C5 (กรณีที่ EGAT อาจแพ้) |
| `--seeds 20 --seed-start 0` | topology ทดสอบ 0-19; fresh = `--seed-start 20` หรือ `40` |
| `--method` | `m0`, `ko` หรือ `<label>=<checkpoint>` (ซ้ำได้) label ต้องขึ้นต้นด้วยชื่อ learner (`egat`, `li`, `yuan`, `q_neutral`) เช่น `egat_nogru_h`, `li_h` ไม่ใช่ `nogru_h` |
| `--agent-set switch_margin=2.0` | hysteresis margin ตอนประเมิน (ใช้กับทุก `--method` ที่เป็น learner ในคำสั่งนั้น) |
| `--set queue_preserve=true` | setting (b): ทุกวิธีเก็บคิวไว้ตอนสลับ (แบบ CSA) |
| `--out` | ไฟล์ JSON ผลลัพธ์ |

ตัวอย่าง (ตาม `runs/v10/eval.sh` และ `runs/v10/nogru_extra.sh`) โฟลเดอร์ `t<k>` = training seed k, `a`/`b` = setting:

```bash
export CUDA_VISIBLE_DEVICES=-1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
mkdir -p runs/v10/t{0,1,2,3,4}/{a,b}
# heuristic (ไม่ขึ้นกับ training seed)
python -m mesh.eval.suite --suite A,B,C --seeds 20 $S --method m0 --method ko --out runs/v10/t0/a/suite_heur.json
# โมเดลหลัก margin 2
for k in 0 1 2 3 4; do
  python -m mesh.eval.suite --suite A,B,C --seeds 20 $S --method egat_nogru_h=runs/v10/ckpt/egat_nogru_s$k.pt \
    --agent-set switch_margin=2.0 --out runs/v10/t$k/a/suite_egat_nogru_h.json
  for b in li yuan q_neutral; do
    python -m mesh.eval.suite --suite A,B,C --seeds 20 $S --method $b=runs/v10/ckpt/${b}_s$k.pt --out runs/v10/t$k/a/suite_$b.json
  done
  python -m mesh.eval.suite --suite A,B,C --seeds 20 $S --method li_h=runs/v10/ckpt/li_s$k.pt --agent-set switch_margin=1 --out runs/v10/t$k/a/suite_li_h.json
  python -m mesh.eval.suite --suite A,B,C --seeds 20 $S --method yuan_h=runs/v10/ckpt/yuan_s$k.pt --agent-set switch_margin=1 --out runs/v10/t$k/a/suite_yuan_h.json
done
```

setting (b): เพิ่ม `--set queue_preserve=true` ใช้ `--suite A,B` และเขียนไปที่ `runs/v10/t$k/b/` (ดู `runs/v10/eval_b.sh`)

topology fresh: `--suite A,B --seeds 20 --seed-start 20` -> `runs/v10/fresh/t$k/{a,b}/` และ `--seed-start 40` -> `runs/v10/fresh2/t$k/{a,b}/` (ชุดยืนยันตาม `docs/paper/protocol_nogru.md`) ทุก suite ต้องมี `suite_heur.json` ใน `t0/<setting>/` ของโฟลเดอร์นั้น

ใช้หลาย core: แต่ละคำสั่งใช้ 1 core สคริปต์ใน `runs/v10/` สร้างรายการงานแล้วส่งให้ `xargs -P 12 -L 1` รันขนาน

ดูผลแบบเร็วของ scenario เดียว (ตัวจำลองค่าเริ่มต้น ไม่มี `--set`):

```bash
python -m mesh.eval.run --scenario S2 --policy ko --seeds 5
python -m mesh.eval.run --scenario S2 --policy egat --checkpoint runs/v10/ckpt/egat_nogru_s0.pt --seeds 5
```

## 10. รายงาน composite และช่วงความเชื่อมั่น

`python -m mesh.eval.composite <ไฟล์ JSON...> --ours <label>` อ่านไฟล์ suite ทั้งหมด รวมผลของ method เดียวกันจากหลายไฟล์ (= หลาย training seed) แล้วพิมพ์รายงาน markdown:

- composite เทียบแต่ละ baseline (A+B และ C): น้ำหนัก aggregate 0.25, jain 0.20, p5 0.20, loss_rate 0.20, ความนิ่ง (จำนวนสลับ) 0.15; +0.10 = ดีกว่า 10%
- ช่วงความเชื่อมั่น: bootstrap 95%, bootstrap ที่สุ่ม training seed ซ้ำ, และ **seed-pair mean กับ 95% t-interval** (นับความแปรปรวนของ training seed ทั้งสองฝั่ง ใช้ในวิทยานิพนธ์)
- Wilcoxon และ bootstrap ราย scenario (Holm), rank เฉลี่ย, ค่าเฉลี่ยรายตัววัด, ความไวต่อน้ำหนัก

ลำดับไฟล์สำคัญ: ไฟล์ที่ i ของแต่ละวิธีถูกจับคู่เป็น training seed เดียวกัน heuristic ไม่มี training seed จึงใส่ไฟล์ heur ซ้ำ 5 ครั้ง ตาม `runs/v10/nogru.sh`:

```bash
cd runs/v10
F=""; for m in egat_nogru_h egat_h2 li yuan q_neutral li_h yuan_h; do F="$F $(echo ./t{0,1,2,3,4}/a/suite_$m.json)"; done
H=./t0/a/suite_heur.json
mkdir -p final
python -m mesh.eval.composite $F $H $H $H $H $H --ours egat_nogru_h > final/composite_a_nogru_test.md
```

(รันจาก `runs/v10` ได้เพราะ `mesh` ติดตั้งด้วย `pip install -e .` หรือใช้ `PYTHONPATH=../..`) ถ้าไม่มี checkpoint ของ `egat_h2` ให้ตัดออกจากรายการ `m` รายงานที่ได้ในวิทยานิพนธ์: `final/composite_{a,b}_nogru_test.md`, `fresh/final/composite_a_nogru.md`, `fresh2/final/composite_{a,b}_nogru.md`

## 12. ns-3

ns-3 ใช้ยืนยันผลเท่านั้น (ไม่ฝึกใหม่): policy ทุกตัวรันฝั่ง Python ส่ง action ให้ ns-3 ผ่าน JSON ทาง stdin/stdout ทีละ step รายละเอียดโปรโตคอลอยู่ใน `docs/ns3/protocol.md`

### 12.1 ติดตั้ง WSL (Windows เท่านั้น)

```powershell
wsl --install -d Ubuntu-24.04
```

repo บนไดรฟ์ `E:` จะเห็นใน WSL ที่ `/mnt/e/MESH`

### 12.2 สร้าง ns-3.47 (ใน WSL หรือ Linux)

```bash
sudo apt update && sudo apt install -y g++ cmake ninja-build python3 python3-pip python3-venv git
mkdir -p ~/ns3_validation && cd ~/ns3_validation
wget https://www.nsnam.org/releases/ns-allinone-3.47.tar.bz2
tar xjf ns-allinone-3.47.tar.bz2 && mv ns-allinone-3.47/ns-3.47 .
cd ns-3.47
./ns3 configure --build-profile=release
./ns3 build
bash /mnt/e/MESH/ns3/build.sh            # Linux: bash <repo>/ns3/build.sh
```

`ns3/build.sh [NS3_ROOT]` คัดลอก `ns3/mesh_bridge.cc` ไปที่ `scratch/` แล้ว build ได้ `~/ns3_validation/ns-3.47/build/scratch/ns3.47-mesh_bridge` (ค่าเริ่มต้น `NS3_ROOT=~/ns3_validation/ns-3.47` และเป็น path เริ่มต้นของ `--binary`) ถ้าใช้ profile อื่น ชื่อไฟล์จะมี suffix เช่น `-default` ให้ส่ง `--binary` ให้ตรง

### 12.3 Python ใน WSL

ns-3 suite รันด้วย python3 ของ WSL จึงต้องติดตั้งไลบรารีในนั้นด้วย (torch รุ่น CPU พอ):

```bash
cd /mnt/e/MESH
python3 -m venv ~/venv-mesh && source ~/venv-mesh/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu

```

(สคริปต์ใน `runs/ns3/` เรียก `python3` ตรง ๆ: ให้ activate venv ก่อนรัน หรือติดตั้งไลบรารีให้ python3 ของระบบ)

### 12.4 รัน

ตรวจเร็วโดยไม่ต้องมี ns-3 (`--fake` ใช้ fluid model แทน):

```bash
python -m mesh.ns3.suite --scenarios S2 --seeds 1 --method ko --fake --out ns3_fake.json
```

การปรับเทียบ (open-loop: ส่ง action และ demand ของตัวจำลองเข้า ns-3 แล้วเทียบ throughput):

```bash
python ns3/calibrate.py --scenario S2 --policy ko --seeds 0-4
```

ชุดทดลองของวิทยานิพนธ์ (S2, B1, B3 x topology 0-4 x training seed 0-4, MAC แบบ RTS/CTS และ base) ใน WSL:

```bash
cd /mnt/e/MESH
bash runs/ns3/run_matrix_v10.sh            # m0, ko, li, yuan, q_neutral
```

ตัวอย่างคำสั่งเดี่ยว:

```bash
python3 -m mesh.ns3.suite --workers 8 --mac '{"rts": 1}' $S --method egat_nogru_h=runs/v10/ckpt/egat_nogru_s0.pt \
  --agent-set switch_margin=2 --out runs/ns3/v10/t0/suite_egat_nogru_h.json
```

เรียกจาก Windows (Git Bash) ต้องกัน path conversion:

```bash
MSYS_NO_PATHCONV=1 wsl.exe -e bash /mnt/e/MESH/runs/ns3/run_matrix_nogru.sh 2
```

จาก PowerShell ไม่ต้องใช้ `MSYS_NO_PATHCONV`: `wsl.exe -e bash /mnt/e/MESH/runs/ns3/run_matrix_nogru.sh 2`

ผล ns-3 ใช้ schema เดียวกับ `mesh.eval.suite` จึงสร้างรายงานด้วย `python -m mesh.eval.composite` ได้เหมือนหัวข้อ 10 (ไฟล์ `runs/ns3/v10/t<k>/suite_*.json`, heuristic อยู่ใน `t0/suite_base.json`)

สคริปต์ใน `runs/` เขียนไว้สำหรับเครื่องที่ repo อยู่ที่ `E:\MESH` (`cd /e/MESH` ใน Git Bash, `/mnt/e/MESH` ใน WSL) ถ้าวาง repo ที่อื่นให้แก้บรรทัด `cd` และ `CK=` ในสคริปต์

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `UnicodeEncodeError: 'charmap' codec can't encode` หรือภาษาไทยเป็นเครื่องหมาย `?` | console Windows ไม่ใช่ UTF-8 | `PYTHONIOENCODING=utf-8` (หัวข้อ 4) หรือ `chcp 65001` ใน cmd; `demo/run_demo.py` ตั้งให้เองแล้ว |
| Git Bash: `wsl.exe -e bash /mnt/e/...` หาไฟล์ไม่เจอ (`C:/Program Files/Git/mnt/e/...`) | Git Bash (MSYS) แปลง path ที่ขึ้นต้นด้วย `/` | `MSYS_NO_PATHCONV=1 wsl.exe ...` หรือเรียกจาก PowerShell |

| ns-3: `TransportError` / `error while loading shared libraries` | binary ไม่มีหรือหา `build/lib` ไม่เจอ | รัน `bash ns3/build.sh` ใหม่; ตรวจว่า `--binary` อยู่ใต้ `<ns-3>/build/` |

| ไฟล์ JSON มี commit ลงท้าย `-dirty` | มีไฟล์ที่ track แล้วแก้แต่ยังไม่ commit ตอนรัน | commit ก่อนรันชุดที่จะรายงาน |
