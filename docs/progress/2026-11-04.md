# ความคืบหน้า 4 พ.ย. 2569

## สรุป
- EGAT v1 และ v2 ผ่านเกณฑ์ gate ที่ลงทะเบียนไว้ล่วงหน้า (composite เฉลี่ยบนชุด A+B ดีกว่า Ko ≥ +10%) ที่ 1 seed: v1 +0.109, v2 +0.112
- แต่ผลยังไม่แข็งแรง: ประมาณ 75% ของคะแนนที่นำมาจาก "ความนิ่ง" (สลับช่อง/เปลี่ยนเส้นทางน้อยกว่า Ko 2–3 เท่า) ส่วน throughput และ fairness ใกล้เคียง Ko
- เริ่มขั้นวัดผลเชิงสถิติ (3 seed เทรน × 20 seed ทดสอบ) และวัดเพดานความสามารถด้วย oracle

## ผลหลัก (seed 0, ทดสอบ 5 seed)

| เทียบกับ | v1 (A+B) | v2 (A+B) |

bootstrap 95% CI ของ v2 เทียบ Ko: [+0.077, +0.144] — ค่าเฉลี่ยเกิน 10% แต่ CI ยังคร่อมเกณฑ์

## สิ่งที่ทำวันนี้
1. เพิ่มการทดสอบนัยสำคัญในรายงาน composite: Wilcoxon แบบจับคู่ต่อ scenario และ bootstrap CI (commit 087f27e)
2. เริ่มเทรน seed 1–2 ของทุกวิธีและประเมิน 20 seed (รันเบื้องหลัง)
3. oracle (รู้ traffic ล่วงหน้า 10 step, ค้นหาเริ่มจากการตัดสินใจของ Ko) เพื่อวัดว่ายังมีพื้นที่ให้ปรับเหนือ Ko เท่าไร — ผลด้านล่าง

## ผล oracle (A+B, 3 seed, เทียบ Ko บนตัวจำลองที่มีต้นทุนการสลับ)
oracle = รู้ traffic ล่วงหน้า 10 step, เริ่มจากการตัดสินใจของ Ko แล้วปรับทีละ node (ใช้วัดเพดาน ไม่ใช่วิธีที่ใช้งานจริง)

| ตัววัด | oracle เทียบ Ko | v2 เทียบ Ko |
|---|---|---|
| composite | **+0.287** | +0.112 |
| aggregate throughput | +15% | +3% |
| p5 throughput | +26% | 0% |
| Jain | +1% | −1% |
| loss rate | −66% | −11% |
| สลับ/เปลี่ยนเส้นทาง | −36% | −57% |

ข้อสรุป: บนตัวจำลองใหม่ยังมีพื้นที่เหนือ Ko มาก (oracle ชนะทุก scenario +0.11 ถึง +0.36) โดยเฉพาะ loss และ p5 → ไม่จำเป็นต้องขยาย action space; โมเดลเราได้มาแค่ราว 40% ของเพดาน และได้มาผ่านความนิ่งเป็นหลัก ส่วน Jain แทบไม่ขยับแม้ใน oracle

## ข้อจำกัดที่ต้องแจ้ง
- ทดสอบ 5 seed ทำให้ Wilcoxon ได้ p ต่ำสุดแค่ 0.0625 จึงยังอ้างนัยสำคัญไม่ได้ → กำลังรัน 20 seed
- ทุกวิธีใน setting (b) (เก็บคิวระหว่างย้าย): v1 +0.073, v2 +0.049 เทียบ Ko — ข้อได้เปรียบส่วนหนึ่งมาจากการเก็บคิว

## แผนพรุ่งนี้ (5 พ.ย.)
- ผลประเมิน 20 seed ของ seed 0 พร้อมนัยสำคัญ
- ออกแบบขั้นถัดไป: ให้โมเดลเรียนจาก oracle แทน Ko (ผู้สอนที่ดีกว่า) และเลือก checkpoint ด้วย composite
