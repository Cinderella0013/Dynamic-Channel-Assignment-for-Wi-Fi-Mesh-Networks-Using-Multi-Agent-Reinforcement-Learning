# คู่มือเดโม EGAT-MAPPO (ขั้น 0-10)

เดโมนี้ย่อขั้นตอนทดลองทั้งหมดของวิทยานิพนธ์ให้รันจบในไม่กี่นาทีต่อขั้น แต่ละขั้นพิมพ์เป็นภาษาไทยว่ากำลังทดสอบอะไร ผลที่ได้ และคำสั่งเต็มที่ใช้ในงานจริง ตัวเลขของเดโมใช้ topology น้อยและ training seed เดียว จึงใช้ดูวิธีการ ไม่ใช่ผลทางสถิติ ผลจริงอยู่ในวิทยานิพนธ์ (ขั้น 7 และ 10 พิมพ์ผลจริงให้เทียบด้วย)

## วิธีรัน

ติดตั้งตาม [คู่มือการใช้งาน](../docs/manual/คู่มือการใช้งาน.md) หัวข้อ 3 แล้วรันจากรากของ repo:

```bash
python demo/run_demo.py                  # ทุกขั้น 0-10
python demo/run_demo.py --stage 4        # ขั้นเดียว
python demo/run_demo.py --stage 6 --stage 7
```

ตัวเลือก:

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--ckpt-dir` | `demo/ckpt` | โฟลเดอร์ checkpoint (`egat_nogru_s0.pt`, `li_s0.pt`, `yuan_s0.pt`, `q_neutral_s0.pt`) |
| `--runs-dir` | `runs` | โฟลเดอร์ผลการทดลองเต็ม ใช้แสดงผลจริงในขั้น 7 (ไม่มีก็ข้ามไป) |
| `--seeds` | 2 | จำนวน topology ต่อ scenario (เพิ่มแล้วช้าขึ้นตามสัดส่วน) |
| `--val-seeds` | 1000 1001 | topology validation ของขั้น 5 |
| `--train-steps` | 2000 | จำนวน step ของการฝึกในขั้น 3 |
| `--workers` | จำนวน core - 2 (ไม่เกิน 12) | จำนวน process ที่รัน episode ขนานกัน |
| `--full-tests` | ปิด | ขั้น 0 รัน pytest ทุกไฟล์ (ราว 20 นาทีขึ้นไป) |
| `--full-report` | ปิด | ขั้น 7 เขียนรายงาน composite เต็มลง `demo/out/composite_demo.md` |
| `--ns3-binary` | `~/ns3_validation/ns-3.47/build/scratch/ns3.47-mesh_bridge` | ns-3 binary (ใน WSL หรือ Linux) |

ผลลัพธ์ของเดโม (JSON และ checkpoint ที่ฝึกในขั้น 3) อยู่ใน `demo/out/` ซึ่งไม่อยู่ใน git สคริปต์ตั้ง `OMP_NUM_THREADS=1`, ใช้ CPU และตั้ง console เป็น UTF-8 ให้เอง จึงไม่ต้องตั้งตัวแปรใด ๆ ก่อนรัน

checkpoint ใน `demo/ckpt/` คือ training seed 0 ของโมเดลที่ใช้ในวิทยานิพนธ์ คัดลอกมาจาก `runs/v10/ckpt/` (รวมราว 2.5 MB) ใช้ checkpoint ชุดอื่นได้ด้วย `--ckpt-dir`

## สิ่งที่อาจารย์จะเห็นในแต่ละขั้น

เวลาในวงเล็บวัดบนเครื่องพัฒนา (Windows 11, 16 core, ns-3 ใน WSL) ดูตารางเวลาจริงท้ายไฟล์

**ขั้น 0: ตรวจสภาพแวดล้อมและ unit test**
แสดงรุ่น Python, numpy, scipy, torch และมี GPU หรือไม่ แล้วรัน unit test ชุดย่อย (ตัวจำลอง, การเลือก action ของ EGAT, สะพาน ns-3 แบบ fake) ต้องเห็น `passed` ทั้งหมด ถ้าไม่ผ่านเดโมจะหยุด

**ขั้น 1: ตัวจำลองและ scenario หนึ่งแบบ**
สร้าง mesh 20 โหนดของ S2 (โหลดสูง 10 Mb/s ต่อโหนด) บอกจำนวน gateway และลิงก์ แล้วรัน Ko หนึ่ง episode (200 step = 20 วินาที) แสดงตัววัดทุกตัว: throughput รวม (aggregate), ความเป็นธรรม (jain), throughput ของ flow ที่แย่สุด 5% (p5), สัดส่วนข้อมูลที่หาย (loss_rate) และจำนวนครั้งที่สลับช่อง/เปลี่ยน parent สังเกตว่า Ko สลับหลายร้อยครั้งต่อ episode

**ขั้น 2: baseline M0 และ Ko**
ตารางตัววัดของ M0 (ช่องเดียว ไม่สลับเลย) และ Ko บน S2, B1, B3 และ composite ของ Ko เทียบ M0 ควรเห็นว่า Ko ได้ throughput สูงกว่ามากและ composite เป็นบวก แต่สลับบ่อย

**ขั้น 3: ฝึก EGAT-MAPPO ไม่มี GRU แบบสั้น**
log การฝึก: ช่วงแรกเป็น behaviour cloning จาก Ko แล้วสลับเป็น MAPPO, บรรทัด `val step ... composite ...` คือการตรวจ validation ที่ใช้เลือก checkpoint และท้ายสุดบันทึกไฟล์ `demo/out/egat_nogru_demo.pt` เดโมฝึก 2,000 step จึงยังไม่เก่ง (composite ติดลบเทียบ Ko ได้) งานจริงฝึก 100,000 step ต่อ seed ราว 3 ชั่วโมง

**ขั้น 4: โหลด checkpoint ที่ฝึกจริง**
โหลด `egat_nogru_s0.pt` ยืนยันว่า `use_gru=False` แสดงจำนวนพารามิเตอร์ แล้วรัน S2 สองครั้ง: margin 0 กับ margin 2 จะเห็นว่า hysteresis ลดการสลับช่องและเปลี่ยน parent ลงมาก โดย throughput ไม่ลด (ในเครื่องพัฒนา: สลับช่อง 111 -> 37 ครั้ง, เปลี่ยน parent 13 -> 2 ครั้ง, aggregate 81.8 -> 84.3 Mb/s)

**ขั้น 5: เลือก hysteresis margin บน validation**
ตารางหนึ่งบรรทัดต่อ margin (0, 1, 2, 4): composite เทียบ Ko, M0, Li, Yuan, Q-neutral ค่าแย่สุด และจำนวนการสลับ เลือก margin ที่ค่าแย่สุดสูงสุด (กฎ worst-case) topology ที่ใช้คือ validation (1000+) ไม่ใช่ topology ทดสอบ งานจริงได้ margin 2 (เดโมอาจได้ 4 เพราะข้อมูลน้อย) ขั้นต่อไปใช้ margin 2 ตามวิทยานิพนธ์เสมอ

**ขั้น 6: ประเมินผลบน A+B เทียบทุก baseline**
ตารางตัววัดเฉลี่ยของ 11 scenario สำหรับ EGAT+H, Ko, Li, Yuan, M0, Q-neutral ควรเห็นว่า EGAT+H ได้ aggregate สูงสุดหรือใกล้สูงสุด loss ต่ำสุด และสลับน้อยกว่า Ko และ Yuan หลายเท่า Q-neutral (ตารางแบบ tabular) แทบส่งข้อมูลไม่ได้

**ขั้น 7: composite score และช่วงความเชื่อมั่น**
composite ของ EGAT+H เทียบแต่ละ baseline พร้อม bootstrap 95% CI ของเดโม จากนั้นพิมพ์ผลจริงในวิทยานิพนธ์ (topology 0-19, 5 training seed: seed-pair mean และ 95% t-interval) เช่น เทียบ Ko +0.260 [+0.230, +0.290] ต้องมี `--runs-dir` ที่มี `v10/final/composite_a_nogru_test.md`

**ขั้น 8: ตรวจความเป็นธรรมด้วย Li+H และ Yuan+H**
ให้ Li และ Yuan ใช้ hysteresis แบบเดียวกัน (margin 1 ที่เลือกด้วยกฎเดียวกัน) แล้วเทียบอีกครั้ง ถ้า EGAT+H ยังนำ แปลว่าข้อได้เปรียบไม่ได้มาจาก hysteresis อย่างเดียว

**ขั้น 9: setting (b) และ topology ใหม่**
composite ของ EGAT+H เทียบ Ko, M0, Yuan+H สองชุด: setting (b) ที่ทุกวิธีเก็บคิวไว้ตอนสลับ (ตัดข้อได้เปรียบเรื่องการสลับน้อย) และ topology seed 40+ ที่ไม่เคยใช้ตัดสินใจใดมาก่อน ควรยังเป็นบวก

**ขั้น 10: ยืนยันด้วย ns-3**
รัน Ko และ EGAT+H ใน ns-3.47 (802.11ax ระดับ packet, RTS/CTS) บน S2 topology 0 ผ่าน WSL แสดงตารางตัววัดและ composite แล้วพิมพ์ผลจริง (EGAT+H นำ Ko +23.1% CI [+15.5, +30.7]) ถ้าไม่มี WSL หรือยังไม่ได้ build ns-3 ขั้นนี้จะพิมพ์ว่า "ข้าม" พร้อมเหตุผล ไม่ล้ม
